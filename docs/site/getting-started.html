First reviewed run

From one script to a deliberate run.

Write ordinary functions, inspect the selected work, decide whether to run it, then review a structured result.

1

Install

The core has no required runtime dependency.

pip install kazeflow
pip install "kazeflow[tui]"  # optional Rich progress display

Keep the quotes around kazeflow[tui]; shells such as zsh otherwise treat the brackets as a filename pattern.

2

Declare a flow in one Python file

An asset is still an ordinary function. A parameter with the same name as another asset declares a dependency. Export a module-level flow to choose the default target.

# daily.py
from kazeflow import Flow, asset

@asset
def fetch() -> str:
    return "report input"

@asset
def publish(fetch: str) -> None:
    print(fetch)

flow = Flow(["publish"])

You can call and unit-test the underlying Python logic normally. kazeflow adds structure around the work order; it does not replace Python with a DSL.

3

Inspect before execution

This shows the target, dependency-first order, configuration, and graph without calling either asset body.

$ kazeflow plan daily.py
Plan: publish
2 assets · no partition selection · default concurrency
Graph:
  fetch
  fetch --> publish *

The * marks the selected target. Use --verbose for normalized plan detail or --format json for automation.

4

Run only after an explicit decision

In a terminal, review the preflight and answer y. In CI or a pipe, pass --yes.

$ kazeflow run daily.py
Planned run:
Plan: publish
2 assets · no partition selection · default concurrency
Graph:
  fetch
  fetch --> publish *
Proceed? [y/N] y
Run result:
- run_id: <run-id>
- status: success
- duration: <duration>
Tasks:
- ✓ fetch (success; <duration>)
- ✓ publish (success; <duration>)

Run IDs and durations vary. Text is for review; use --format json when another program needs one portable result document.

5

Understand the before and after

ValuePurpose
FlowPlanTargets, tasks, dependencies, partition selection, and normalized configuration before execution.
RunResultTerminal flow, task, and attempt statuses, timings, outputs in memory, and failure metadata after a normal completion.
Logs and execution eventsOptional time-ordered progress and diagnostics; they do not replace the plan or final result.

Asset failures appear in a completed RunResult. External cancellation or a failing event consumer propagates instead of inventing a terminal result.

Use the same workflow from Python

from kazeflow import run

plan = flow.plan({"max_concurrency": 2})
for task in plan.tasks:
    print(task.name, task.dependencies, task.partition_keys)

result = run(["publish"], {"max_concurrency": 2})
print(result.status, result.duration)
for task in result.tasks:
    print(task.task.task_name, task.status)

The Python result retains in-memory outputs. Portable JSON and stored records intentionally omit arbitrary raw outputs, exception objects, and partition-key values; see results and history.

Before you load a script:

Python module loading can execute top-level code, imports, and an explicitly selected factory. Planning skips decorated asset bodies only after loading. kazeflow helps review trusted flow structure; it is not a sandbox, a safety proof, or automatic approval.
