Review after execution

See the outcome, then keep only what you choose.

A completed text run tells you each task's terminal status and duration. A structured result is also returned to Python. Storage is always an explicit opt-in.

Read a result in the terminal

kazeflow run daily.py --yes
kazeflow run daily.py --yes --verbose

The normal text summary includes the run ID, overall status, duration, and each task's status. Failed tasks include portable error type and message; skipped tasks include a reason. --verbose adds attempt-level detail without showing raw partition keys, outputs, exception objects, or tracebacks.

Save a run only when you request it

kazeflow run daily.py --yes --store .kazeflow/runs.sqlite3

Without --store, kazeflow does not create a database. With it, the CLI writes the terminal portable record after the run completes.

Find, inspect, and compare stored runs

# The default read location is ./.kazeflow/runs.sqlite3
kazeflow runs list
kazeflow runs show RUN_ID
kazeflow runs compare LEFT_RUN_ID RIGHT_RUN_ID

# Or select a store explicitly.
kazeflow runs list --store path/to/runs.sqlite3

Use --format json when another tool needs a stable single-document result. Text output is for human review; it can evolve while preserving its documented meaning.

Portable by design.

Stored and JSON records intentionally omit raw asset output, exception objects, and raw partition-key values. This keeps a result useful to inspect without pretending arbitrary Python values are safe or portable records.
