Select a slice deliberately

Plan one date. Then run that date.

A partitioned asset represents independent slices of one task—often dates, regions, files, or tenants. Your Python definition owns what keys mean; the CLI lets you select them explicitly.

Declare a partitioned asset

from kazeflow import DatePartitionDef, Flow, asset

@asset(partition_def=DatePartitionDef())
def publish_daily() -> None:
    print("publish the selected day")

flow = Flow(["publish_daily"])

An unpartitioned asset runs once. A partitioned asset creates one attempt per selected key. When dependencies are partitioned, kazeflow keeps attempts and their terminal status distinct.

Review before rerunning

# Inspect one partition without executing asset bodies.
kazeflow plan daily.py --target publish_daily --partition-key 2026-08-08

# Execute exactly that selected key after explicit approval.
kazeflow run daily.py --target publish_daily --partition-key 2026-08-08 --yes

Repeat the same entry, target, partition, and concurrency options when moving from a separate plan command to run. The run command also plans again in the same process before asking for approval.

Select more than one partition

kazeflow plan daily.py \
  --partition-key 2026-08-08 \
  --partition-key 2026-08-09

--partition-key (or --partition) is repeatable. CLI values are strings passed to the script's partition definition; kazeflow does not guess a type or manufacture today's date.

Know what selection means

InputMeaning
Omit --partition-keyNo explicit CLI selection; the partition definition determines the planned work.
Pass one or more keysRequest those exact textual values from the partition definition.
Python API empty selectionAn explicit empty tuple represents no partition work when the flow supports it.
Falsey Python keys0, "", and False remain present values, not omission.

Review attempts without leaking keys

The in-memory Python RunResult can retain the real partition key and output for the caller. CLI JSON, RunResult.to_record(), and SQLite records keep only whether a partition was present. They retain attempt order, status, timing, skip reason, dependency blockers, and portable failure metadata without persisting raw keys.

A failed partition can coexist with successful independent partitions. Inspect attempt-level status with text --verbose or the in-memory Python result when that distinction matters.

Plan is still a loading operation.

The CLI must load trusted Python before it can ask the partition definition which keys are valid. Planning does not invoke decorated asset bodies, but it does not sandbox the import.
