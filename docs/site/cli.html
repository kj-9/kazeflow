Complete command reference

Inspect what will run.

The zero-dependency CLI is a review layer over normal Python. Text is for people; JSON is the stable automation boundary.

Commands

CommandUse it for
kazeflow assets ENTRYList assets discovered while loading a trusted entry.
kazeflow plan ENTRYReview targets, dependency order, partition selection, configuration, and graph without invoking asset bodies.
kazeflow run ENTRYReview a preflight, explicitly approve, execute, and print the terminal result.
kazeflow runs listList records in an existing local SQLite store.
kazeflow runs show RUN_IDShow one portable stored record.
kazeflow runs compare LEFT RIGHTCompare portable run and task aggregates.

Entry forms and asset discovery

kazeflow assets daily.py
kazeflow plan daily.py:flow
kazeflow plan package.module:flow
kazeflow run package.module:make_flow --yes

A bare .py file prefers its module-level flow. Without one, kazeflow uses assets registered while that file loads and derives all terminal assets as default targets. An explicit attribute can be a Flow or a zero-argument factory returning one; factories are never guessed implicitly.

Plan options

kazeflow plan ENTRY \
  [--target NAME ...] [--partition-key KEY ...] \
  [--max-concurrency N] [--verbose] \
  [--format text|json|mermaid|dot]

--target and --partition-key are repeatable. --verbose is text-only. The JSON projection is deliberately lossy and never exposes raw partition-key objects. Use JSON rather than parsing text whitespace.

Choose the graph that fits the review

# Concise graph in the terminal.
kazeflow plan daily.py

# Paste into GitHub Markdown or another Mermaid renderer.
kazeflow plan daily.py --format mermaid

# Render later with an external Graphviz tool.
kazeflow plan daily.py --format dot > flow.dot

Mermaid output is readable graph source:

$ kazeflow plan daily.py --format mermaid
flowchart LR
    task_0["fetch"]
    task_1["publish (target)"]
    task_0 --> task_1

kazeflow does not install or invoke Mermaid or Graphviz. These outputs always describe the same resolved plan as text and JSON.

Run options and approval

kazeflow run ENTRY \
  [--target NAME ...] [--partition-key KEY ...] \
  [--max-concurrency N] [--yes] [--tui] [--store PATH] \
  [--verbose] [--format text|json]

run writes its preflight to standard error before any asset body runs. When input and error streams are terminals it asks Proceed? [y/N]; only y or yes proceeds. Declining is a successful no-op. Non-interactive execution requires --yes.

JSON mode writes exactly one portable result to standard output after a terminal run; preflight, prompt, TUI progress, and diagnostics stay on standard error. --verbose adds safe attempt detail in text mode only.

Optional adapters

pip install "kazeflow[tui]"
kazeflow run daily.py --tui
kazeflow run daily.py --yes --store .kazeflow/runs.sqlite3

--tui lazily loads Rich and shows plan-aware progress on standard error. --store initializes the chosen SQLite database only after a terminal result exists. Neither adapter is imported on the default core path. Adapter failure is an infrastructure failure and takes precedence over an asset-failure exit status.

Exit statuses

StatusMeaning
0Successful inspection or run, including deliberately declined confirmation.
1A confirmed run completed with an asset failure.
2Invalid syntax/configuration, missing non-interactive --yes, ambiguous selection, or unknown stored run ID.
3The entry could not be loaded or resolved.
4Execution infrastructure, TUI, store, or history database failed.

Errors and diagnostics use standard error. Failed configuration, loading, or infrastructure produces no successful JSON document.

Compatibility and scope

Documented commands, options, exit statuses, and JSON schemas are public CLI interfaces. Human text can improve in layout while preserving meaning. The CLI adds no scheduler, daemon, remote execution, cache, sandbox, or automatic approval.

Loading is part of trust.

Entry resolution executes Python import-time code and an explicitly selected factory. assets and plan do not invoke decorated asset bodies after loading, but they do not make untrusted Python safe. Review the source and environment first.
